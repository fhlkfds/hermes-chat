# The approval mode is a composer pill that shows what Hermes reports

Issue #277. The owner wants to change how Hermes approves dangerous commands in the middle of a chat (Smart, Manual or YOLO) and always see the mode Hermes is actually using. Until now the app had only a YOLO switch in the status bar. The research note `docs/research/hermes-approval-mode-mid-session.md` found that Hermes keeps two facts: the profile's `approvals.mode` (`smart`, `manual` or `off`, in its config.yaml) and each session's own YOLO flag. `session.info` reports `approval_mode` and one `yolo`, which is the session's flag OR the mode being `off` OR Hermes's `--yolo` launch flag.

## Decisions

- **Smart and Manual are the profile's; YOLO is the chat's** (the research note's section 8, "option C"). Smart or Manual sends `config.set approvals.mode` with the profile, which reaches every chat on the profile, CLI and messaging sessions too, from Hermes's next guarded command. YOLO sends `config.set yolo` for this chat's session alone. A chat's flag beats the mode, so Smart or Manual in a chat Hermes reports as YOLO turns its flag off first, then writes the mode. The mode is written even when Hermes already reports it, so a stale report still converges (`writesFor` in `src/hermes/approvals.ts`).
- **A pill in the composer, after the reasoning pill.** The owner picked it from a prototype of three placements: the composer, the chat header and the status bar. It sits with the other things the owner sets for the next turn, the model and the reasoning effort. The header holds the chat's own actions, and the status bar can be hidden, which would hide a safety state. The pill is shown only on a started chat, since YOLO belongs to a chat's session and only a session reports approvals; the New chat pane has none. In a composer narrower than 600px its label hides and its icon and chevron stay, so the model name keeps its room at an 820px window. Its accessible name always carries the full mode.
- **The face shows only what Hermes reports.** "Smart", "Manual", "YOLO · this chat" (the chat's flag, or `--yolo`), "YOLO · all chats" (the mode is `off`), or "Approvals", disabled with the reason, until Hermes reports. Nothing changes on a click. A pick keeps the menu open until Hermes answers, and nothing dismisses it meanwhile, since a sent write can't be taken back; then it closes; a refusal (4030 for an administrator-pinned key on newer Hermes, 4002 for a locked key on `f0d94882`) shows Hermes's message in the menu, and the face stays as Hermes reports it.
- **The settle rule.** Against the deployed Hermes (`f0d94882`, `~/.cache/hermes-live-277/proof.log`), each write is followed by two `session.info` frames for the written session, both before the answer, and one of them can be stale, in either order:
  - `config.set yolo off` was followed by `{approval_mode: "manual", yolo: false}`, then a stale `{manual, yolo: true}`, then the answer `"0"` (proof.log lines 112 to 115).
  - `config.set approvals.mode manual` was followed by a stale `{smart, false}`, then `{manual, false}`, then the answer (lines 57 to 62).

  So the last frame before an answer can be wrong, and no later frame may come for a long time (none during a turn). While a pick is under way for a session, `session.info` updates everything for it except its approvals. Once Hermes has answered, the approvals are Hermes's own formula over the answers: the mode from the `approvals.mode` answer, else the mode reported before the pick, and YOLO when the `yolo` answer is `"1"` or the mode is `off`. When a write is refused, the rule settles from the writes Hermes did answer. When Hermes refused the only write, the approvals stay as Hermes reported them before the pick. The next `session.info` after the pick is trusted again. Picks run one at a time on the connection, so a pick sent before the last was answered starts from what that one settled, and two chats on the profile can't each settle on a different mode.
- **The YOLO warning is shown every time YOLO is turned on**, before anything is sent. It says that other chats still ask, that writes to AGENTS.md, CLAUDE.md and SOUL.md still ask, and that commands on Hermes's blocklist are still blocked. Cancel has focus. Picking YOLO in a chat that is already YOLO, by its own flag or because the profile's mode is `off`, does nothing: under `off` the flag would change nothing visible and outlast a later mode change.
- **`off` is shown, not offered.** The menu offers Smart, Manual and YOLO. A profile set to `off` elsewhere shows "YOLO · all chats", and Smart or Manual sets it back.
- **The status bar's YOLO switch is removed.** The pill replaces it, so there is one control for one setting. A status bar saved with the old `yolo` item still shows its other items.

## Considered options

- **Trusting `session.info` around a write, as the YOLO switch did.** The race above makes the last frame before an answer stale in either direction, so the face could settle on the mode the owner just left.
- **Trusting the click.** The face would show what was asked, not what Hermes does, which is the gap the issue is about.
- **Detecting the `--yolo` launch flag**, from a `yolo: true` report after Hermes answered the chat's flag off. Dropped with the settle rule: the stale frames make that report unreliable around a write, and outside a write the report can't tell the launch flag from the chat's flag.
- **The chat header or the status bar for the control.** See the placement decision.
- **A per-chat Smart or Manual.** Hermes has no per-session mode. It needs the server change in the research note's section 9.

## Consequences

- **The `--yolo` gap.** On a Hermes launched with `--yolo` (`HERMES_YOLO_MODE`), every chat reports YOLO. Right after Smart or Manual, the answers say the chat's flag is off, so the face shows the mode although Hermes still runs every command without asking. The next `session.info` outside a pick, such as one after a model change or a mode change from another client, puts it back to "YOLO · this chat".
- **Smart and Manual reach beyond the chat.** They change every chat on the profile, including CLI and Telegram sessions, which the menu says. Another open chat on the profile moves to the new mode when Hermes re-sends its `session.info`.
- **A chat opened before its agent is built shows "Approvals" briefly** (about 0.3 s on the test server). The create and resume answers carry no approvals; the first `session.info` with them arrives once Hermes has built the session's agent, before the first prompt.
