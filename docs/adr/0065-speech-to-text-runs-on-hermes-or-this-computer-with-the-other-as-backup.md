# Speech to text runs on Hermes or on this computer, with the other as backup

Issue #192 asks to pick where Dictation and voice conversations (ADR 0041) turn speech into text: on the Hermes server, as today, or on the computer running Hermes Chat, or both, with one as the automatic backup for the other. On this computer the owner picks a Whisper model size and language, sees its size and whether it is downloaded, downloads or deletes it, sees where it is kept, or points at a model file they already have. A Test records a few seconds and shows what each option heard and how long it took. #220, the narrower "use an engine already installed here" step, wasn't built or started, so its detection work is part of this change.

## Decisions

- **The engine is whisper.cpp's `whisper-cli`, run by Rust** (`src-tauri/src/local_stt.rs`). It is the engine whose model files are the five sizes #192 names (tiny, base, small, medium, large-v3, as ggml files), it is a single program with no Python, and it reads the 16 kHz mono WAV the recorder already makes (`toWav`), so the recording needs no conversion. The program is the one the owner picked in the native Open dialog, or else the first `whisper-cli`, `whisper-cpp` or `whisper.cpp` that is a runnable file in an absolute `PATH` folder. A picked program that is gone is reported, not swapped for one on `PATH`. The webview never names a program or a path: picks go through the Open dialog, and the webview only asks for "engine" or "model".
- **It runs as a fixed argument list, privately, with a timeout.** `-m <model> -f <recording> -l <language> -nt -np -t <threads>` (no shell). The recording is written to a new `0700` folder under the temp dir, as a `0600` file created with `create_new`, and the folder is deleted when the run ends, however it ends. The run is killed past its timeout (`kill_on_drop`). Only a WAV (`RIFF…WAVE`) of at most 25 MB is taken, Hermes's own limit, so both sides take the same recordings. Nothing about the audio or the text is logged or kept. The output's segment lines are joined, and a segment that is a whole bracketed marker (`[BLANK_AUDIO]`, `(silence)`) is dropped, so silence reads as no speech.
- **Models come from whisper.cpp's own repository and are checked.** `https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-<size>.bin`, with each size's exact byte count and SHA-256 pinned from the repository's LFS listing (read 2026-11-04). A download streams into a hidden `.part` file in `<app data>/whisper-models`, is cut off if it grows past the size, and is renamed into place only when the size and checksum match; anything else is deleted. One download runs at a time and can be cancelled. A size counts as downloaded when its file is there at its exact size. Delete removes only those five files. A model file the owner picked is used instead of a size, and "Stop using it" forgets it without touching the file.
- **Where each setting is kept.** The engine, model size, language and picked model file are Rust's, in `local-stt.json` in the app data folder, written whole (temp file, rename) and read back after every change: what the screen shows is what was read back, and a file that doesn't read back as written is an error. A malformed field falls back to its default on its own. Primary, Backup and the timeout are display preferences (`speechToText` in `uiPrefs.ts`), since only the webview uses them.
- **One router for Dictation and voice conversations** (`transcribeRouted` in `src/hermes/sttRoute.ts`, used by `Main`'s `VoiceApi.transcribe`). It runs the primary; if that throws (Hermes not connected or unreachable, a provider error, no engine or model here, whisper.cpp failing) or, with a backup, takes longer than the timeout, it runs the backup on the same recording. An empty transcript is an answer, not a failure: the owner said nothing. A late answer from a timed-out primary is dropped. The primary is timed only when a backup is waiting; otherwise it gets as long as it takes, and this computer stops itself after 10 minutes. When the backup gave the text, Dictation shows a note (a status, not an alert) and a voice conversation's "What Hermes got" shows it under the turn: "Transcribed on this computer. Hermes couldn't transcribe it: …". When both fail, the error says what each said, and Dictation keeps the recording to try again, as before.
- **"This computer" can't be made the primary until it can run**: the button is off, with the reason as its title, until an engine and a model are there. If it later can't run (the model deleted, the program gone), it stays picked and the section says so, with what happens next: the backup is used, or Dictation fails until it is fixed.
- **Dictation works offline when this computer is in the route.** With "This computer" as primary or backup, the microphone isn't blocked while Hermes is disconnected; if this computer isn't set up either, the note after the recording says why. A voice conversation still needs Hermes, which it sends each turn to.
- **Hermes's side reuses Speech providers** (ADR 0055): the Speech to text section names the profile's provider and says to pick it and its model under Speech providers, on the same tab. No second picker.
- **Test** records four seconds with the same recorder as Dictation, then has each side that can be tried transcribe that one recording, one after the other, and shows the text, the time and the provider or model. A side that can't be tried (not connected; nothing set up here) says why instead.

## Considered options

- **whisper-rs (whisper.cpp linked into the app).** Rejected for now. It needs cmake and a C++ toolchain at build time, adds a large native build to every `cargo build`, and pins a whisper.cpp version to the app's releases. Running the program the owner installed keeps the app small and lets the owner choose a GPU build.
- **faster-whisper, OpenAI `whisper`, Vosk** (#220's list). Not now: each is a Python install with its own model cache and formats, so "see its size, download or delete it" can't be done the same way. A picked `whisper-cli` covers owners with a custom build; others can follow.
- **Keep everything in uiPrefs.** Rejected: the engine and model paths decide what program runs and what file it reads, so they must be set only through Rust's Open dialog, never written by the webview.
- **Time the primary even with no backup.** Rejected: with nothing to switch to, a timeout only throws away a slow but good transcript.

## Consequences

- An owner can dictate with no audio leaving the computer, offline too, and have Hermes catch the cases the local model can't (or the other way round), seeing which one did it.
- The pinned checksums follow whisper.cpp's repository as of 2026-11-04. If it replaces a file, the download is refused as not matching until the pins are updated.
- whisper.cpp's command-line flags (`-nt`, `-np`, `-l auto`) are those of v1.9.5. A much older or newer build that changes them fails with whisper.cpp's own error, shown as the reason.
- Verified with a real whisper.cpp v1.9.5 built on the build box and the real `tiny` model (`a_real_whisper_cpp_transcribes_when_one_is_given`, run with `HERMES_TEST_WHISPER_*` set). See the pull request for what was run.
