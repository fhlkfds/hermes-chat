# A reply's file changes are undone one file at a time, from the checkpoint its time names

> **Accepted.** Issue #601, first PR. The model is `src/hermes/fileChanges.ts`, the undo `src/hermes/fileUndo.ts`, the chip and the Preview's files view `src/ui/FileChanges.tsx`, and the capability `checkpoints` in `src/hermes/capabilities.ts`.

The owner wants to see which files each bot reply changed on the server, see the diff, and put files back one at a time without losing the edits they made by hand. Hermes `bf0203a` and `f0d9488` keep checkpoints of a chat's folder when `checkpoints.enabled` is on, and serve them as `rollback.list`, `rollback.diff` and `rollback.restore` on `/api/ws` (`tui_gateway/methods_tools.py:1123-1183`). A checkpoint carries only a hash, a time to the whole second and a reason. It names no chat, turn or message. `rollback.diff` compares a checkpoint with the files as they are now, cuts the diff at 4000 characters, and answers an empty diff when it fails. The facts below were measured on a real Hermes `bf0203a` on 2026-11-15 (`docs/research/fleet-features-server-support.md`, "Time machine for files a bot changed").

## Decisions

- **The app counts a reply's files itself.** Each successful `write_file` and `patch` in the reply counts, from `tool.start` and `tool.complete` with their `args` for a live reply, and from the stored tool rows for a chat's history. An edit Hermes refused, whose result has an `error` or `success: false` (`agent/display.py` `_result_succeeded`), doesn't count. A tool item keeps the edit's `inline_diff`, from `tool.complete` or the stored row's `display_metadata`, for the hand-edit check. A `patch` in V4A mode names no `path`, so it isn't counted.
- **The checkpoint is found by time, and an ambiguous one is refused.** It is the oldest checkpoint from the seconds the reply ran in, from its message's second to its last reply's, leaving out the "pre-rollback snapshot" each restore takes. Git keeps a checkpoint's time rounded down to the second, so every bound is a reply time rounded down too. Hermes lists the newest first, so of two in one second the later in the list is the older. When that checkpoint is from the second the previous reply ended in, it may be the previous reply's, and the Preview says it can't tell rather than guessing. When none is left, as after Hermes keeps only the 20 newest of a folder, it says so. A reply with no time yet, still running or not stamped by Hermes, has no chip, and one with no time to start from (no message time and no reply before it) finds none, since any checkpoint the folder keeps would fit.
- **Only one-file restores are sent.** Every restore is `rollback.restore {hash, file_path}`, with the file's path relative to the chat's folder. The restore function takes a branded `RelPath`, which only `placeIn` makes, so a call without a file doesn't compile, and a test checks every restore the app sends names one. A one-file restore checks the file out of the checkpoint and leaves the chat alone.
- **The stat decides which files differ.** A reply's file can be undone only when `rollback.diff`'s stat lists it, by its path or git's `.../tail` for a long one. The stat isn't cut, where the diff is. A file the stat doesn't list is as it was before the reply. A file outside the chat's folder, or named with `~`, isn't covered by the folder's checkpoints. A file whose name has `*`, `?`, `[`, `\` or a leading `:` isn't offered: Hermes checks a one-file restore out without literal pathspecs (`checkpoint_manager.py:1343`), and with git 2.47 restoring `foo[1].txt` also restored `foo1.txt` (measured).
- **A created file is shown, not offered.** Its diff section says `new file mode`, and a one-file restore of a path the checkpoint lacks fails with "pathspec … did not match" and leaves the file (measured). The Preview says to delete it by hand.
- **A hand edit is judged against the bot's last edit of the file.** That is the last successful edit anywhere in the loaded transcript; when it is in a later reply, the Preview also warns that the undo takes back that reply's change. A `write_file` was left as-is only when the file is exactly its `content`, and a `patch` only when each hunk's after-text in the last edit's `inline_diff`, its context and added lines with the ANSI colours taken out, must still be in the file. For both, every line the file's `rollback.diff` section adds or takes away must be one that the bot's own edits of the file since the checkpoint added or took away, which catches a hand edit outside the bot's hunks, and a checkpoint (of the folder, maybe taken for another chat) older than the text the bot replaced. A cut `inline_diff`, a missing one, a section past the 4000-character cut, or a file that can't be read whole is "can't tell". Undo this turn lists every file it would restore with a checkbox, and a file edited by hand, or one the app can't tell about, starts unchecked.
- **Every undo is preview, refuse if changed, write, read back** (ADR 0110, ADR 0024). The preview is the diff and each file's text as shown. On Undo the app reads both again and restores nothing if either changed. It then restores the chosen files one per call, in order, and stops at the first that fails. Last it reads the diff again: a restored file must be gone from the stat, and its text must have changed, since Hermes answers a failed diff as an empty one. A file whose text can't be read back is unconfirmed. Each file is reported as restored, still differing although Hermes answered success, not restored, or not tried. Undo is off while the chat has a reply running.
- **The chip hides where Hermes takes no checkpoints.** The capability probes `rollback.list` with a made-up session ("session not found", 4001, means present) and reads `checkpoints.enabled` from `GET /api/config` for its Diagnostics row. Once per live session, the app sends `rollback.diff` with a hash that can't be one. Hermes refuses it for a chat whose terminal runs in a container (5022, "Checkpoints are not taken for terminal.backend=…") before it reads the hash, and answers an empty diff on the host without running git. The chip doesn't show without the methods or in a container. With the profile's checkpoints off, it reads "· checkpoints are off", and the Preview says to set `checkpoints.enabled: true` and start a new chat.
- **The canonical gateway's rows are from its source.** `rollback.list`, `rollback.diff` and `rollback.restore` have `APP_VERBS` rows (ADR 0174): the session authority answers all three for a live session (`gateway/session_tui_ops.py:205`), in the legacy shapes. They are marked unprobed, since they were added after the gateway was recorded. The app refuses that protocol, so the chip never shows there.

## Considered options

- **Hermes's whole-folder safe restore for Undo this turn.** It keeps files the agent-write ledger says the owner edited, but a successful whole-folder restore also drops the chat's newest message and everything after it, whatever checkpoint it restores (`methods_tools.py:1154`). Undoing any reply but the newest would remove the wrong message. It may come back for the newest reply only, in a later PR.
- **Diffing the checkpoint before a reply against the one after it.** That would show exactly what the reply changed, but no method compares two checkpoints. The Preview shows the diff to the files now, and says when a later reply changed a file too.
- **Matching a checkpoint to a turn by its reason.** The reason is only "before write_file", "before patch" or "before terminal: …". It names no turn.

## Consequences

- With checkpoints off, Hermes's default, the chip says so and nothing can be undone until the owner turns them on and starts a new chat.
- Two replies in one second, or a reply that started in the second the previous one ended in, can't be undone from the chip.
- A hand edit that only repeats a line the bot itself added or removed in the file isn't seen. A patched file past the diff's cut can't be judged, so it starts unchecked.
- A diff past 4000 characters shows only its first part, and a file past the cut is listed with no diff.
- FakeHermes keeps checkpoints per folder (`fakeCheckpoints.ts`), and the verify stand-in runs a turn that edits two files on a prompt saying "edit two files", with `POST /__file` to edit one by hand.
